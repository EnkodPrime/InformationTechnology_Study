# Тема 2. Операционни системи
Обхват: 11 глави (ch00–ch10), glossary.js (55 термина), 8 C файла, 8 теста. Първо прегледах незавършените промени от прекъснатата проверка (9 файла): всички са запазени, една е довършена. После направих пълна проверка.
Независими проверки:
- Python референтен симулатор на планирането с различна структура: FCFS, SJF, SRTF, RR, PRIO, PPRIO върху трите набора от C и предварителната настройка „Гладуване“. Всички диаграми на Гант, суми и брой превключвания съвпадат.
- Python референтна реализация на FIFO (deque), LRU (OrderedDict), OPT и Clock върху поредицата на Silberschatz и класическата поредица на Белади за 1–6 рамки.
- Python реализация на first/best/worst fit и на алгоритъма на банкера (Silberschatz).
- UBSan възпроизвеждане на препълването на RR опашката в HEAD версията и стрес тест на поправената версия (10 процеса × 20 единици, RR q=1, SRTF, PPRIO).
- Всички 8 C файла са компилирани с -Werror и пуснати под -fsanitize=address,undefined.

## Проверено и вярно (кратко)
- **Планиране.** Примерът от ръководството дава FCFS 20/3, SJF 8/3, RR q=2 16/3 при отговор 6/3. Наборът x дава FCFS 19, SJF 16, SRTF 12, RR 28, PRIO 22, PPRIO 20. Твърдението „RR при q ≥ най-дългата задача = FCFS“ е вярно. Формулите за обръщане, чакане и отговор са верни.
- **Банкерът** (Silberschatz 5×3, Available 3 3 2): състоянието е безопасно с ред P1,P3,P4,P0,P2. P1 (1 0 2) се удовлетворява. P0 (0 2 0) след това води до небезопасно състояние и чака. P4 (3 3 0) чака, защото няма ресурс. P0 (8 0 0) е грешка, защото надвишава Need.
- **Заместване** (7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1, 3 рамки): FIFO 15, LRU 12, OPT 9, Clock 14. Жертвите съвпадат с референтната реализация. Схема 18 (1 2 3 1 4): FIFO изхвърля 1, LRU изхвърля 2.
- **Белади** (1 2 3 4 1 2 5 1 2 3 4 5): FIFO дава 9 при 3 рамки и 10 при 4. LRU (10→8) и OPT (7→6) са монотонни. Твърдението „LRU и OPT нямат аномалия“ е вярно (stack algorithms, Mattson et al. 1970).
- **Fit:** layouts за first/best/worst съвпадат. Примерът „дупки 2 и 3 не дават 4“ е верен.
- **MMU:** 12345 при 4096 → страница 3, отместване 57, рамка 10 → 41017. TLB miss ≠ page fault ≠ диск. Copy-on-write и нулевата страница минават без диск.
- **Deadlock:** четирите условия на Coffman са необходими. При единични екземпляри цикъл ⇔ deadlock. При много екземпляри цикълът е необходим, но не е достатъчен.
- **Синхронизация:** загубено увеличение при ABABAB. Редът wait(empty) → wait(mutex) е обоснован правилно. Условна променлива с while (POSIX spurious wakeups). Дефиницията на data race е съвместима с C11 5.1.2.4.
- **Файлови системи:** inode се освобождава при nlink=0 и без отворени дескриптори (POSIX unlink()). Висяща символна връзка. Таблицата непрекъснато/свързано/индексно: 1 / k+1 / 2 четения.
- **Журнал:** срив преди commit дава старо състояние, след commit се прави replay. Журнал ≠ резервно копие. Успешен write() ≠ данните са на носителя (POSIX fsync).
- **Имена:** Linux е ядро, Ubuntu и Debian са дистрибуции, Android е изграден върху Linux ядро. POSIX = Portable Operating System Interface. UNIX не е акроним. Примерите за RTOS са верни. ext4, XFS, NTFS, APFS, FAT32 и exFAT са файлови системи.
- **Речник:** всички английски термини и определения са коректни.
- **Тестове:** run_tests 8/8 глави, 0 разлики (300 сверки). clickall: 0 грешки. Всички 8 C файла са чисти под ASan/UBSan с -Werror. bundle е обновен.
