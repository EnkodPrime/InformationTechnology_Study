# Tema_11_Mrezhi — Компютърни мрежи
Обхват: 13 глави (js/ch00–ch12), 11 C файла (c/01–11), речник (~150 термина), 11 теста. Всички визуализации (algos) и сравнителни таблици са прегледани.
Независими проверки:
- Кадърът от капсулирането (101 B) е разбран в Python: IPv4 контролната сума е проверена (резултат 0), TCP сумата с псевдо-заглавие също дава 0. Total Length е 83, TCP дължината е 63, а FCS е сверен със `zlib.crc32` (`43 AE F9 69`, записан LE). Полетата на заглавията са сверени с RFC 791 и RFC 9293 §3.1 (IHL 5, DF=0x4000, proto 6, data offset 5, флагове 0x18=PSH|ACK) и с IEEE 802.3 (Ethernet II, EtherType 0x0800, минимум 60 B + FCS = 64).
- Препращането (hop1/hop2) е проверено: TTL намалява с 1, сумата се преизчислява (320D→330D→340D, съвпада с инкременталното правило), нов FCS.
- Интернет контролната сума за `AB CD EF`, `FF FF 00 01` и `45 00 00 53` е пресметната с независима Python реализация и съвпада.
- CRC-32 е сверен със `zlib.crc32` за "123456789"=CBF43926, "abc" и 00. Полиномът 0x104C11DB7 има 15 члена (нечетен брой).
- Modbus CRC-16 е пресметнат с независима Python реализация: `01 03 00 00 00 01`→`84 0A`, `11 03 00 6B 00 03`→`76 87` (примерът от спецификацията), `01 03 02 00 FA`→`38 07`. MBAP е сверен с Modbus Messaging on TCP/IP Implementation Guide (length=6).
- Подмрежите (/24, /26, /8, /20, /31, /32, /25, /0) са сверени с `ipaddress`. Longest prefix match е сверен с `ipaddress` за 5 цели.
- TCP сегментите и състоянията са сверени с RFC 9293 §3.3.2/3.5/3.6. Проверени са ISN, x+1, y+1; SYN и FIN заемат по 1 номер; CLOSE_WAIT→LAST_ACK; TIME_WAIT. При затворен порт отговорът е RST+ACK с seq=0, ack=x+1 (§3.10.7.1).
- CAN арбитражът е пресметнат ръчно (доминантна 0, жично И, MSB first): 0x100 срещу 0x180 → 0x100; {0x7F0,0x123,0x124,0x0FF} → 0x0FF; {0x555,0x554,0x55C} → 0x554.
- QNAME кодирането е сверено с RFC 1035 §3.1. Проследен е DNS кешът с TTL. URL разборът е сверен с RFC 3986 (фрагментът не се изпраща).
- Формулите за закъснение са пресметнати наново: 1500 B @ 100 Mbit/s = 120 µs; 3000 km при 2·10⁸ m/s = 15 ms; BDP = R·RTT; eff = min(R, W/RTT).
- LIN PID е пресметнат по LIN 2.x (P0 = ID0⊕ID1⊕ID2⊕ID4, P1 = ¬(ID1⊕ID3⊕ID4⊕ID5)).
- Всички C файлове са компилирани с -Werror и са чисти под -fsanitize=address,undefined.

## Проверено и вярно (кратко)
- Байтовете на Ethernet II, IPv4 и TCP заглавията, позициите на полетата (14/34/54), DF, протокол 6, data offset, флаговете PSH+ACK, прозорец 64240, псевдо-заглавието (src, dst, 0, 6, TCP length). Минимален кадър 60+4.
- Интернет контролната сума (RFC 1071): end-around carry, нечетен байт, проверка → 0. Преизчисляване при промяна на TTL.
- CRC-32: начало FFFFFFFF, отразен EDB88320, финално инвертиране, FCS LE. Проверката CBF43926 е вярна.
- Комутаторът (учене от изпращача, наводняване, филтриране, преместване) и ARP решението (me&mask == dst&mask) са верни.
- Подмрежите (вкл. /0, /31, /32) и LPM са сверени с `ipaddress`. NAT с портове и твърдението „NAT ≠ защитна стена“ са верни.
- TCP: SYN/SYN+ACK/ACK, номерата, FIN, CLOSE_WAIT/LAST_ACK/FIN_WAIT_2/TIME_WAIT и RST при затворен порт (RFC 9293). Рамкирането с префикс за дължина е вярно.
- DNS QNAME (RFC 1035), кешът с TTL, NXDOMAIN; DNSSEC не шифрова. DHCP портове 67/68 и broadcast от 0.0.0.0.
- HTTP/3 върху QUIC/UDP; QUIC не е акроним (RFC 9000); URL фрагментът не се изпраща (RFC 3986 §3.5).
- Формулите за закъснение и всички числови примери (120 µs, 15 ms, BDP, eff, util).
- CAN: доминантна 0, MSB first, недеструктивен арбитраж, по-малкият ID печели; Classical CAN 8 B, CAN FD 64 B. EtherCAT 0x88A4.
- LIN: до 20 kbit/s, до 8 B. FlexRay: 10 Mbit/s на канал, до 254 B, статичен/динамичен сегмент, NIT.
- Modbus: FC03, RTU CRC (LE), MBAP, порт 502, 40001 като референтен номер.
- Bluetooth: Classic 79×1 MHz, LE 40×2 MHz, 3 първични advertising канала; Battery Service 0x180F, Battery Level 0x2A19 (0–100); до 7 активни peripherals в piconet; notification без потвърждение, indication с потвърждение; CCCD.
- Речник: определенията и английските термини са прегледани, без фактически грешки (MBAP = Modbus Application Protocol header — съвпада със спецификацията).
- C кодът няма UB под ASan/UBSan. JS и C съвпадат (тестове: 0 разлики).
