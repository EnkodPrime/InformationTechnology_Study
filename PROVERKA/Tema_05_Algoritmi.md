# Тема 5. Алгоритми
Обхват: 12 раздела (ch00–ch11), glossary.js (~80 термина + локалните речникови записи в ch02–ch10), 10 C файла, всички algos функции. В началото нямаше незавършен diff, работното дърво беше чисто. Независими проверки (node/gcc, в scratchpad):
- Брой извиквания при Фибоначи: наивно = 2F(n+1)−1 за n = 0…25; с мемоизация = 2n−1 за n ≥ 1.
- pow_lin, pow_twice и pow_fast: преброени извиквания срещу затворени формули.
- Шестте сортировки, 300 случайни входа с повторения: коректност и стабилност (мехурче, вмъкване и сливане са стабилни; при пряк избор, бързо и пирамидално е наблюдавана нестабилност). Броят сравнения е проверен при сортиран и обратно сортиран вход, а при пирамидалното — при всички равни ключове.
- Merge Sort: броят копирания при n, което не е степен на 2.
- B&B за TSP: 300 случайни несиметрични матрици с 3–6 града, сравнени с пълно изброяване (0 разлики). „Най-близък съсед“ е сравнен с оптимума.
- Ферма и Милър–Рабин върху 561, 1105, 1729, 2465, 2821, 91 и 1000003.
- Раница 0/1 (2D и 1D надолу) и неограничена (1D нагоре): 200 случайни случая срещу изчерпване и отделна DP (0 разлики).
- Колац(27) = 111 стъпки; N дами: 2, 10, 4 и 92 решения за n = 4, 5, 6, 8; Дейкстра с отрицателно ребро срещу Белман–Форд.
- Всички C файлове са минати с -Werror и ASan/UBSan. Поведението на is_even при gcc -O2 е проверено отделно.

## Проверено и вярно (кратко)
- P ⊆ NP. Определение на NP чрез сертификат/проверител. NP-пълна = NP ∩ NP-трудна. Посоката на сводимостта (известна трудна A ≤ₚ нова B). HC ≤ₚ TSP (тегла 1/2, K = n): доказателство в двете посоки, f е полиномиална. SAT като първа задача (Кук–Левин). 2-SAT ∈ P, 3-SAT е NP-пълна. Проблемът за спирането е NP-труден и неразрешим, а оптимизационният TSP — NP-труден. Картата е изрично условна при P ≠ NP.
- Стабилност и сложности на сортировките: пряк избор ≡ n(n−1)/2 сравнения, ≤ n−1 размени, нестабилно. Мехурче с ранно спиране: n−1 сравнения при сортиран вход, n(n−1)/2 при обратен, стабилно. Вмъкване: n−1 / n(n−1)/2, стабилно. Сливане: стабилно благодарение на <=, Θ(n) буфер. Lomuto: n(n−1)/2 сравнения и дълбочина n−1 при сортиран вход (последен опорен) — проверено: 66 и 11 при n = 12. Долната граница Ω(n log n) при сортиране чрез сравнения и защо counting sort не я нарушава.
- Броячите на сравнения/размени/записи в JS съвпадат с C (1547 сверки). Броячът „записи“ е последователен (размяна = 2).
- Ферма: Кармайкъл (561 = 3·11·17, 1105, 1729, 2465, 2821) минават за всички взаимно прости основи, а Милър–Рабин ги хваща (основа 2). Свидетелят дава сигурно „съставно“ (едностранна грешка). Границата ≤ 4⁻ᵏ при Милър–Рабин (Rabin 1980, ≥ 3/4 свидетели за нечетно съставно n). powmod в C е uint64 при n < 2²⁶, без препълване.
- B&B за TSP: границата cost + minOut[последен] + Σ minOut[непосетени] е допустима (оптимистична) и при несиметрични матрици. Всяко довършване излиза точно веднъж от последния и от всеки непосетен град. 300 случайни матрици дават 0 разлики с изчерпването. Отрязването е при b ≥ best.
- Фибоначи: наивно 2F(n+1)−1 = Θ(φⁿ) извиквания; мемо 2n−1 (n ≥ 1); таблица Θ(n) памет; две променливи Θ(1).
- Раница 0/1: рекурентната връзка, O(nW) е псевдополиномиално, разпознаващата версия е NP-пълна. Посоката на 1D обхождането (надолу → 0/1, нагоре → неограничена) е проверена срещу независими реализации.
- Евклид: инвариант и рангова функция. Колац(27) = 111. BFS и изчерпване в краен граф. Диагоналният аргумент. Разрешими ⊂ полуразрешими. Тезата на Чърч–Тюринг е теза.
- O/Ω/Θ: примерът 3n²+5n+7 с c₂ = 4 → n₀ = 7 (49 ≥ 42; 36 < 37), c₂ = 10 → n₀ = 2. Удвояването дава ⌊log₂n⌋+1. Триъгълният цикъл дава n(n+1)/2. Средно (n+1)/2 сравнения при линейно търсене.
- mid = lo + (hi−lo)/2 (препълването е UB). Двоичното търсене прави ≤ ⌊log₂n⌋+1 итерации.
- Алчен подход: интервали по най-ранен край (аргумент за замяна, полуотворени интервали), контрапримерите за другите три стратегии. Монети {1,3,4} при сума 6; {1,2,5,10,20,50} е канонична (до 400 няма контрапример). Дейкстра с отрицателно ребро дава грешен резултат (сравнено с Белман–Форд).
- 2-приближение за върхово покритие (аргумент чрез съчетание). Среща по средата: O(2^(n/2)·n).
